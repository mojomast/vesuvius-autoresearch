# Research C: Type Safety & Schema

Config handling is dominated by `Dict[str, Any]` in `autoresearch.py`, `experiments/runner.py`, and dashboard config summaries. Typed boundaries are most valuable around experiment configs, run rows, metric payloads, proposals, strategy phase payloads, and promotion automation results.

Proposed pydantic v2 schema in `src/autoresearch/schemas.py`:

- `ModelConfig`: `name`, `input_mode`, `depth`, `hidden_units`, `base_channels`.
- `DatasetConfig`: `research_scope`, `train_npz`, `val_npz`, `extra_train_npzs`, `prepared_root`, `patch_size`, validation metadata.
- `TrainingConfig`: `epochs`, `batch_size`, `learning_rate`, `weight_decay`, `pos_weight`, sample budgets, seeds, augmentation, sampling, loss weights.
- `EvaluationConfig`: `main_metric`, `threshold`, `tta_flips`, calibration and positive-rate cap fields.
- `AutoresearchConfig`: metadata generated by proposal/promotion flows.
- `OutputsConfig`, `ValidationSetup`, `ResolvedDataConfig`.
- `ExperimentConfig`: top-level model with permissive `extra="allow"` during migration.

Strict-mode annotation candidates: `_clamp_param`, `_config_cost_tier`, `_promotion_gate`, `_run_quality_score`, `_search_signature`, `_proposal_candidates`, `_propose_configs`, `validate_metric_contract`, `_validate_reported_promotion_outputs`.

Breaking changes to handle carefully: unknown model names fail earlier, string booleans/numbers may normalize or fail, train/val NPZ pairs validate earlier, empty seed lists fail earlier, promotion run profiles need required metadata, and historical DB configs must remain loadable with compatibility defaults.
